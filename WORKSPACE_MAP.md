## File-class quick reference

See `INDEX.md` § "Cognition file taxonomy" for the canonical class table.
Key rule: a file's class determines who can edit it and how.

| Class | Who edits | When |
|-------|-----------|------|
| **CANONICAL** | Governor only, via proposal + user approval | Rare |
| **HOT** | Governor (mostly); per-session edits on STATE.md | Frequent |
| **OPERATIONAL** | Various; manifests frozen at start | Per block |
| **DERIVED** | Orchestrator (auto) | On command |
| **TRANSIENT** | Orchestrator (auto) | Per scan |
| **GOV-PRIVATE** | Governor only | As needed |

## Worktree convention

A Domain Agent's worktree path is **always**:

```
.claude/worktrees/<domain>-<slug>/
```

Where:
- `<domain>` is the package name without `packages/` prefix (e.g.,
  `identity`, `analytics`, `ui-kit`).
- `<slug>` is a 3-6 word descriptor of the block (e.g., `mfa`,
  `revenue-kpi`, `chart-component`).

The branch inside the worktree is **always**:

```
agent/<domain>/block-<NNN>-<slug>
```

The Governor's `governor scan` enumerates worktrees by globbing
`.claude/worktrees/*/` (configured in `orchestrator.config.yaml` under
`repos[0].worktrees_glob`). Any worktree outside this convention is
invisible to the Governor.

## How to extend the layout

To add a new path class (e.g., `infrastructure/k8s/`):

1. Decide its file class (CANONICAL? OPERATIONAL?).
2. Decide its owner (Governor? DevOps Agent? a Domain Agent?).
3. Update this file with the new path.
4. Update `INDEX.md` if the path is part of a HOT/WARM/COLD tier.
5. Update `orchestrator.config.yaml` if the orchestrator needs to scan
   or audit it.
6. Open a Governor proposal in `.governor/proposals/` and get user
   approval before creating files in the new path.
